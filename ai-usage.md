# AI Usage

I used Claude (via Claude Code) as a drafting and implementation tool throughout this assignment. I did not paste the assignment questions into the AI. Instead, I described the general topic of each section and guided every step: what to focus on, which trade-offs to surface, where things can go wrong, and what edge cases matter. The AI drafted prose and wrote code under my direction; I reviewed, corrected, and edited every output.

| Section | How I used AI | What I directed and decided |
|---|---|---|
| **Q1 — Production Incident** | Claude drafted the structure, hypothesis table, decision tree diagram, and stakeholder communication template based on my guidance | I framed the incident as a finality problem (not a bug); identified H5 (re-run without PIT) as the top suspect and H7 (another source changed) as the one most people miss; defined the three unknowns that shape the investigation; insisted on "both numbers can be correct"; directed every trade-off and edge case |
| **Q2 — Pipeline Design** | Claude wrote the design document — sizing arithmetic, Iceberg comparison, extraction/merge/gold flow, GDPR vs finance section, backfill plan, cost table, and the adaptive correction window — following my step-by-step direction | I set assumptions A1–A7 and insisted on validating with the partner first; drove the merge-not-overwrite decision from the "no total count" constraint; identified the rate-limit ceiling as the central design tension (not volume or compute); directed the GDPR-vs-finance framing; specified the backfill priority and go-live strategy; reviewed all arithmetic and cost estimates |
| **Q3 — SQL & Data Modeling** | Claude wrote the PostgreSQL queries, boundary assumption table, validation plan, and built the Docker Compose sandbox with the test fixture and Python oracle | I set the `[)` boundary convention (end_date = first inactive day); confirmed the "active AND paying" reading; decided cross-product overlaps should be included with a flag; specified every edge case user and their expected results; verified the oracle logic |
| **Q4 — Set Game** | Claude wrote the Python implementation (features, card, deck, rules, game loop), the 39 pytest tests (including exhaustive 1,080-sets check and mutation testing), the web UI, the class UML diagram, and the design document | Claude did most of the implementation work. I confirmed the set-size check over mod-3 for readability after discussing both options. |
| **Q5 — AI Data Agent** | Claude drafted the architecture document: design principles, component diagram, DAU-drop walkthrough, permission model, evaluation plan, and the orchestrator deep dive | I set the core principles ("agent has no permissions of its own" and "typed, narrow tools — not free SQL"); Claude suggested LookML as the metric source — I reviewed it but don't have hands-on experience with it, so I accepted his reasoning; directed the pipeline-failure walkthrough to demonstrate architecture generality; specified the prompt-injection defence approach; decided the rollout sequence |
